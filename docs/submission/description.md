# Firexp — Project Description (draft)

_Paste into Devpost "What it does / How it works". ~380 words, English._

**Firexp turns passive group TV into a shared, branching story the room decides together — from their phones.**

**The problem.** Watching together is passive. Every "what would you do?" stays in your head, and most interactive films tie the choice to one remote-holder.

**How it works (4 steps).**
1. The Fire TV shows a QR code. Each viewer joins a phone web page — no app install.
2. A short questionnaire sets the room's profile as numeric "flags."
3. During playback, decisions appear **only on the phones**. Viewers vote; the tally moves live and votes are revocable until the timer closes.
4. The Fire TV plays **continuous video** and silently cuts to the branch the room chose — flags select the clip. Different rooms reach different endings.

**What makes it different.** The TV never breaks immersion — there is no decision UI on screen; all interaction lives on the second screen (the inverse of Amazon X-Ray: X-Ray informs, Firexp gives control). The story goes with the room, not with one person. After the episode each viewer sees "your room chose A · 62% of rooms chose B," a route recap generated by **Amazon Bedrock**, and their own decision profile — a hook to replay and reach the ending only 8% of rooms saw.

**For creators.** A React CMS lets creators build the branching **graph** — not the versions — visually (React Flow), with a flag simulator and static validation that flags "fake choices" (decisions with no downstream effect) before the audience notices.

**Stack.** Kotlin + Jetpack Compose on Fire OS with **Media3/ExoPlayer** (prefetch for seamless branch cuts; decoder fallback so a bad clip never blacks out the story). A deliberately "dumb" WebSocket relay handles real time (rooms, live tally, host/lobby, late-join). A stateless content API on **Amazon DynamoDB** is the source of truth; video lives on private **S3 + CloudFront (OAC)**; **Amazon Bedrock** generates decision prompts and recaps. A shared TypeScript `story-graph` package is the **single branching engine** — the same code drives the TV, the CMS simulator, and validation, verified by cross-language fixtures. Everything is infrastructure-as-code (**AWS CDK**).
